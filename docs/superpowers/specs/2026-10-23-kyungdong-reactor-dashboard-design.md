# 경동글로벌텍 반응기 통합 데이터 대시보드 설계

## 1. 목적

경동글로벌텍의 `반응기_리포지토리`를 기반으로 경영진과 실무자가 함께 사용하는 통합 대시보드를 구축한다.

- 경영진은 수주, 견적, 고객, 품목과 프로젝트 진행 현황을 한눈에 파악한다.
- 실무자는 프로젝트별 수주, 도면, 견적, 구매, 납기와 관련 문서를 추적한다.
- 모든 지표는 원본 문서 또는 색인 데이터까지 추적 가능한 근거를 제공한다.
- 원본 리포지토리는 수정하지 않고 읽기 전용으로 연결한다.

## 2. 범위

### 포함

- `R01`부터 `R12`까지의 반응기 프로젝트 12건
- 프로젝트 및 설계 데이터: `bom/data/cases_pipeline.json`
- 문서 색인: `index/files.csv`
- 견적 색인: `index/quotes.csv`
- 원본 문서 열기 및 존재 여부 확인
- 경영 현황, 프로젝트 관리, 견적 분석, 도면·BOM, 문서 검색, 데이터 품질 화면
- 로컬 단일 명령 실행과 Docker Compose 실행

### 제외

- 31GB 전체 원본 자료의 전면 색인
- 원본 문서 수정, 이동 또는 삭제
- DWG/CAD 파일의 브라우저 렌더링
- OCR 및 생성형 AI 문서 질의응답
- ERP, MES, 그룹웨어 실시간 연동
- 자동 견적 승인 또는 설비 제어

## 3. 사용자와 핵심 업무

### 경영진

- 확인된 계약·발주 근거를 기준으로 수주액과 수주 프로젝트 수를 확인한다.
- 유효한 경동 발행 견적과 수주 전환 현황을 확인한다.
- 연도, 고객, 품목과 프로젝트 상태별 분포를 비교한다.
- 계약 누락, 납기 변경, 최신 도면 미확정 같은 주요 위험을 확인한다.

### 실무자

- 프로젝트를 상태, 고객, 연도와 키워드로 검색한다.
- 프로젝트별 수주 → 설계 → 구매 → 납품 흐름과 근거 문서를 확인한다.
- 최신 도면, 개정 이력, BOM, 노즐과 설계조건을 조회한다.
- 견적 변경 이력과 매출·매입 견적을 구분한다.
- 파일명, 확장자, 분류와 프로젝트로 원본 문서를 찾고 연다.

## 4. 정보 구조와 화면

### 4.1 공통 셸

- 좌측 내비게이션과 상단 전역 검색·필터를 사용한다.
- 핵심 내비게이션은 `경영 현황`, `프로젝트`, `견적 분석`, `도면·BOM`, `문서 검색`, `데이터 품질`로 구성한다.
- 데스크톱을 우선 설계하고 태블릿 너비에서도 핵심 카드와 표를 사용할 수 있게 반응형으로 만든다.
- 짙은 네이비와 스틸 그레이를 기본으로 사용하고, 안전 오렌지를 경고와 주요 액션의 강조색으로 사용한다.

### 4.2 경영 현황

- KPI: 확인된 수주액, 유효 견적액, 수주 프로젝트 수, 고객 수, 견적→수주 전환율
- 차트: 연도별 수주·견적 추이, 고객별 금액, 품목/용량별 구성
- 현황: 프로젝트 단계별 건수와 확인 필요 항목
- 모든 KPI와 차트는 적용된 집계 기준과 포함 프로젝트를 확인할 수 있어야 한다.

### 4.3 프로젝트

- 상태, 고객, 연도와 키워드 필터를 제공한다.
- 카드와 표 보기를 제공하고 수주·도면·견적·참고 파일 수를 표시한다.
- 프로젝트 상세는 다음 탭으로 구성한다.
  - 개요: 고객, 품목, 코드, 상태, 계약일, 수주액, 납기, 주요 메모
  - 견적: 견적번호, 일자, 발행구분, 금액과 변경 이력
  - 도면·설계: 최신 도면, 도면번호, 개정일, 해독 상태, 설계조건
  - BOM·구매: 부품, 재질, 규격, 수량과 구매발주 내역
  - 문서: 수주, 도면, 견적, 참고 문서

### 4.4 견적 분석

- 기본 집계는 `해당건견적=O`인 행만 포함한다.
- 경동 발행 매출 견적과 협력사·DYSC 등 매입 견적을 분리한다.
- 동일 견적번호 또는 동일 프로젝트의 변경 이력을 시간순으로 표시한다.
- 연도, 고객, 발행구분과 프로젝트 필터를 제공한다.

### 4.5 도면·BOM

- 도면 파일, 도면번호, 일자, 최신본 여부와 해독 상태를 검색한다.
- BOM은 부품명, 재질, 규격과 수량으로 필터링한다.
- 노즐과 설계조건은 프로젝트별로 조회한다.
- 읽기 실패 또는 최신본 미확정 항목은 경고 배지로 구분한다.

### 4.6 문서 검색

- 프로젝트, 대분류, 세부구분, 확장자와 키워드로 검색한다.
- 파일 크기, 수정일, 텍스트 추출 여부와 원본 경로를 표시한다.
- 원본이 존재할 때만 파일 열기 기능을 활성화한다.

### 4.7 데이터 품질

- 계약서·발주서 없음
- 수주액 미확인
- 최신 도면 미확정
- DWG/CAD 읽기 실패
- 견적 금액 또는 적용 대상 확인 필요
- 원본 파일 경로 끊김

각 항목은 프로젝트와 근거 파일로 이동할 수 있어야 한다.

## 5. 아키텍처

### 프런트엔드

- React와 TypeScript로 단일 페이지 애플리케이션을 구현한다.
- 차트, 데이터 표, 필터와 프로젝트 상세 화면을 독립 컴포넌트로 분리한다.
- 서버 상태와 화면 상태를 구분하며 URL에 주요 필터를 반영한다.

### 백엔드

- FastAPI가 읽기 중심 REST API와 색인 갱신 명령을 제공한다.
- 데이터 적재, 지표 계산, 검색, 원본 파일 경로 검증을 별도 서비스로 분리한다.
- 원본 파일 열기는 허용된 반응기 리포지토리 아래의 색인된 경로만 대상으로 한다.

### 저장소

- SQLite에 프로젝트, 주문, 견적, 파일, 도면, BOM, 노즐, 구매, 품질 이슈를 정규화해 저장한다.
- 원본 파일 자체는 SQLite나 프로젝트 폴더로 복사하지 않는다.
- 최초 실행과 명시적인 재적재 명령에서 원본 색인을 읽어 SQLite를 갱신한다.

## 6. 데이터 적재와 집계 규칙

### 기준 데이터

- 프로젝트, 수주, 도면, BOM, 노즐, 설계조건과 구매: `cases_pipeline.json`
- 문서 메타데이터와 해시: `files.csv`
- 견적 메타데이터: `quotes.csv`

### 수주 집계

- 계약서 또는 고객 발주서로 금액이 확인된 프로젝트만 확인 수주액에 포함한다.
- R06, R07, R08처럼 수주 상태이나 계약·발주 금액이 없는 프로젝트는 건수에는 포함하고 금액은 `미확인`으로 표시한다.

### 견적 집계

- 기본 유효 견적은 `해당건견적=O`인 행만 포함한다.
- `경동 발행`은 매출 견적, 협력사 및 공급사 발행은 매입·참고 견적으로 구분한다.
- 표준양식에 남은 과거 시트와 해당 건이 아닌 견적은 기본 KPI에서 제외한다.
- R12의 전체 플랜트 견적은 반응기만의 금액으로 확정할 수 없으므로 핵심 반응기 견적액에서 제외하고 참고 견적으로 표시한다.

### 전환율

- `수주 프로젝트 수 / 유효 경동 발행 견적 프로젝트 수`로 계산한다.
- 금액 기준 전환율은 계약과 견적의 대상 범위가 일치하지 않는 사례가 있어 초기 버전에서는 제공하지 않는다.

### 데이터 변경

- 재적재는 원본을 수정하지 않고 현재 데이터를 읽어 멱등적으로 갱신한다.
- 원본 경로와 MD5를 보존해 파일 추적과 변경 탐지를 지원한다.
- 값이 없거나 서로 충돌할 때 임의로 보간하지 않는다.

## 7. API 경계

- `GET /api/health`: 서비스와 데이터 적재 상태
- `GET /api/dashboard/summary`: KPI와 차트 데이터
- `GET /api/projects`: 프로젝트 목록과 필터
- `GET /api/projects/{id}`: 프로젝트 상세
- `GET /api/quotes`: 견적 목록과 분석 데이터
- `GET /api/drawings`: 도면·설계 검색
- `GET /api/bom`: BOM 검색
- `GET /api/files`: 문서 검색
- `GET /api/quality/issues`: 데이터 품질 이슈
- `POST /api/admin/reindex`: 로컬 관리자용 재적재
- `GET /api/files/{id}/open`: 허용 경로 안의 원본 파일 열기 또는 다운로드

초기 버전은 사내 로컬 사용을 전제로 한다. 공개 네트워크 배포 전에는 인증, TLS, 감사 로그와 접근권한을 추가해야 한다.

## 8. 오류 처리와 보안

- 일부 데이터 적재 실패가 전체 대시보드 기동을 막지 않도록 소스별 오류를 기록한다.
- 계산할 수 없는 KPI는 0으로 위장하지 않고 `확인 불가`로 반환한다.
- 원본 경로가 없으면 메타데이터는 표시하되 파일 열기를 비활성화한다.
- CSV 인코딩은 UTF-8 BOM을 처리하고 필수 컬럼 누락 시 명확한 오류를 남긴다.
- 파일 접근은 구성된 원본 루트와 색인된 파일에만 허용하고 경로 순회를 차단한다.
- 사용자 입력과 API 쿼리는 허용된 정렬·필터 목록으로 검증한다.

## 9. 실행과 배포

- 로컬 개발은 단일 실행 스크립트로 프런트엔드와 API를 함께 시작한다.
- 운영 또는 시연용으로 Docker Compose를 제공한다.
- 원본 데이터 경로는 환경변수로 주입하며 저장소에 절대경로를 하드코딩하지 않는다.
- 샘플 또는 테스트용 축소 데이터는 실제 원본과 분리한다.

## 10. 검증

- 적재 테스트: JSON/CSV 파싱, BOM·도면·견적 관계, 재적재 멱등성
- 집계 테스트: 수주액, 유효 견적액, 전환율, R12 제외 규칙
- API 테스트: 필터, 페이지네이션, 누락 데이터, 잘못된 ID와 경로 차단
- 프런트엔드 테스트: 로딩, 빈 상태, 오류, 필터, 상세 전환
- 브라우저 검증: 데스크톱과 태블릿 레이아웃, 표 스크롤, 차트, 파일 열기
- 원본 불변성 확인: 테스트 전후 원본 해시 및 수정 시각이 변경되지 않음

## 11. 완료 기준

- 사용자가 한 번의 명령으로 대시보드를 실행할 수 있다.
- 12개 프로젝트와 관련 견적·도면·BOM·문서를 조회할 수 있다.
- 경영 KPI가 명시된 집계 규칙과 일치한다.
- 모든 주요 수치와 품질 경고에서 근거 프로젝트 또는 파일로 이동할 수 있다.
- 원본 파일을 수정하지 않으며 허용된 경로 밖의 파일에 접근할 수 없다.
- 자동화 테스트와 실제 브라우저 점검이 통과한다.
