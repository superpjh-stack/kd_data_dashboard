# 경동글로벌텍 전체 데이터 대시보드 확장 설계

## 1. 목표

경동글로벌텍 `20261003 자료` 전체를 읽기 전용으로 분석해 고려솔더 데이터 플랫폼과 같은 데이터셋 중심 업무 화면으로 제공한다. 경영진은 연도·고객·프로젝트·견적·수주 현황을 확인하고, 실무자는 원본 수집 이력, 정제 결과, 문서·도면·미디어와 데이터 품질을 추적한다.

기존 반응기 12건 대시보드는 정제된 기준 데이터로 유지하고 전체 프로젝트 포트폴리오에 포함한다.

## 2. 조사 기준 현황

- 전체 파일: 9,036개
- 전체 용량: 약 30.6GB
- 2025년 폴더: 3,726개, 약 12.22GB
- 2026년 폴더: 4,983개, 약 18.04GB
- 반응기 정제 리포지토리: 326개, 약 0.31GB
- 사진: 4,831개
- PDF: 1,284개
- DWG/CAD: 1,212개
- XLSX/XLS: 400개
- 영상: 101개
- DOCX/DOC/HWP/HWPX: 139개

실행파일, DLL, CAD 임시·백업 파일, 다운로드 잔여 파일과 업무 무관하거나 유해 가능성이 있는 HTML이 섞여 있으므로 전수 노출하지 않고 별도 격리한다.

## 3. 범위

### 포함

- `25 경동도면함`, `26 경동도면함`, `반응기_리포지토리`
- 프로젝트, 고객, 문서, 견적, 계약·발주, 거래, 도면·BOM, 사진·영상 메타데이터
- 파일 원장과 MD5 기반 중복 그룹
- 자동 추출 결과와 검토·게시 상태
- 고려솔더 형식의 데이터셋 목록, 수집 이력, 검증 결과, 원본·정제값 비교, 게시 데이터
- 기존 반응기 상세 분석과 전체 프로젝트 간 연결

### 제외

- 원본 파일 수정·이동·삭제
- 사진·영상 내용의 AI 판독
- CAD 도면의 브라우저 렌더링
- 자동 계약·견적 승인
- 실행파일 또는 위험 HTML 실행·열기
- 공개 인터넷 배포와 외부 사용자 인증

## 4. 사용자 경험

화면은 고려솔더 데이터 플랫폼과 동일한 정보 밀도와 흐름을 따른다.

- 상단: 경동글로벌텍 브랜드, 데이터 기준 시각, 연결 상태
- 좌측: 접근 가능한 데이터셋 목록과 새로고침
- 우측: 선택 데이터셋의 설명, 수집 이력, 검증 결과, 원본·정제 비교, 게시 데이터
- 데이터 상태는 `수집`, `처리 중`, `검토 필요`, `게시 가능`, `게시됨`, `격리`로 표현한다.
- 강한 색상은 선택 상태, 오류와 검토 필요 상태에만 사용한다.
- 표는 가로 스크롤과 안정적인 페이지네이션을 제공한다.

## 5. 데이터셋 구성

### 5.1 종합 현황

- 연도별 프로젝트 수와 파일 규모
- 고객별 프로젝트·문서·견적 현황
- 견적·수주 금액과 확인되지 않은 금액
- 문서·도면·사진·영상 구성
- 중복, 미분류, 해독 실패와 격리 파일

### 5.2 프로젝트 데이터

- `KD25xx`, `KD26xx` 프로젝트 번호
- 연도, 고객, 품목·설비, 상태, 기간
- 연결된 견적, 계약·발주, 도면, 구매, 사진·영상 수
- 반응기 12건의 정제 프로젝트와 전체 프로젝트 연결

### 5.3 견적 데이터

- 견적일, 견적번호, 수신처, 품명, 합계금액, VAT, 발행구분
- 프로젝트 연결과 해당 건 여부
- 같은 파일 안에 남은 과거 시트 분리
- 동일 견적의 버전·변경 이력
- 매출 견적과 공급사·협력사 매입 견적 분리

### 5.4 계약·구매·거래 데이터

- 계약서, 고객 발주서, 경동 구매발주, 거래명세서, 세금계산서, 성적서
- 문서일, 거래처, 금액, 납기, 프로젝트 연결
- 문서 종류별 누락과 확인 필요 상태

### 5.5 도면·BOM 데이터

- DWG, CAD, DXF, STEP, IPT, SLDPRT, SLDASM
- 도면번호, 파일일, 개정 후보, 프로젝트, 설비·부품 연결
- 조립도, 부품도, 계산서와 참고 도면 분류
- `.bak`, `.dwl`, `.dwl2`, `.log`는 운영 도면에서 제외
- 기존 반응기 BOM·노즐·설계조건 유지

### 5.6 사진·영상 데이터

- 프로젝트, 폴더, 파일명, 확장자, 크기, 수정일
- 원본 파일 열기와 프로젝트 상세 연결
- 이미지·영상 내용 분석 결과로 오인할 수 있는 자동 태그는 만들지 않는다.

### 5.7 데이터 품질

- 프로젝트 번호 미확인
- 고객 또는 문서 종류 미분류
- 금액·일자 추출 실패
- 동일 내용 중복
- 최신 도면 미확정
- 텍스트 없는 스캔 PDF
- CAD 해독 실패
- 원본 경로 끊김
- 실행파일·DLL·임시파일·위험 HTML 격리

## 6. 데이터 모델

SQLite에 다음 엔터티를 저장한다.

- `sources`: 2025, 2026, 반응기 정제 소스
- `ingestion_runs`: 스캔·추출 실행과 상태
- `projects`: 프로젝트 번호, 연도, 고객, 명칭, 상태
- `customers`: 정규화 고객명과 원문 변형
- `files`: 경로, 확장자, 크기, 수정일, MD5, 프로젝트, 분류
- `documents`: 문서 종류, 문서일, 당사자, 금액, 납기, 추출 근거
- `quotes`: 견적번호, 품명, 금액, VAT, 발행구분, 해당 건 여부
- `drawings`: 도면번호, 종류, 개정 후보, 해독 상태
- `bom_items`: 부품, 재질, 규격, 수량과 근거 도면
- `media`: 사진·영상 메타데이터
- `validation_issues`: 오류 코드, 심각도, 원본값, 정제값, 검토 상태
- `published_versions`: 검토 후 조회에 사용하는 데이터 버전
- `duplicate_groups`: MD5와 대표 파일

각 자동 추출 레코드는 원본 파일 ID, 추출 방법과 신뢰 상태를 보존한다.

## 7. 프로젝트 정규화

- 최상위 `KD25xx`, `KD26xx` 폴더를 기본 프로젝트로 사용한다.
- `KD2500`, `KD2600` 견적 폴더의 하위 작업번호는 별도 견적 프로젝트 후보로 만든다.
- 고객명은 폴더명과 문서 값을 함께 보존한다. 정규화 이름과 원문을 분리한다.
- 여러 프로젝트가 섞인 파일은 하나로 강제 배정하지 않고 다중 연결 또는 검토 필요 상태로 둔다.
- 기존 반응기 `R01`~`R12`는 대응하는 KD/GD 프로젝트 코드와 연결한다.

## 8. 처리 파이프라인

1. 파일 전수 스캔과 기본 메타데이터 수집
2. MD5 계산과 중복 그룹 생성
3. 프로젝트·고객 후보 추출
4. 파일 종류와 업무 문서 유형 분류
5. XLSX/XLS, PDF, DOCX/DOC, HWP/HWPX, EML 텍스트·표 추출
6. 견적·계약·발주·거래·도면 구조화
7. 원본값·정제값·검증 문제 생성
8. 검토 가능한 버전 저장
9. 승인된 버전 게시

재실행은 파일 경로, 크기, 수정일과 MD5를 비교해 변경된 파일만 다시 처리한다.

## 9. 파일별 처리 정책

- XLSX: 시트명, 셀 값, 저장된 계산값과 표 구조를 읽는다.
- XLS: 가능한 판독기를 사용하고 실패하면 원본 메타데이터와 실패 사유를 남긴다.
- PDF: 텍스트 PDF를 우선 추출한다. 스캔 PDF는 OCR 필요 상태로 둔다.
- DOCX: 문단과 표를 추출한다.
- DOC/HWP/HWPX: 사용 가능한 변환 도구로 추출하고 실패를 명시한다.
- EML: 발신·수신·일자·제목과 본문, 첨부 메타데이터를 추출한다.
- CAD/3D: 파일 메타데이터와 도면번호 후보를 수집한다. 임의 형상 해석은 하지 않는다.
- JPG/PNG/MP4/WMV: 메타데이터만 수집한다.
- EXE/DLL/CAB/OCX/TLB/COM: 실행하지 않고 격리한다.
- BAK/LOG/DWL/DWL2/TMP/CRDOWNLOAD: 운영 데이터에서 제외하고 파일 품질 현황에 포함한다.
- HTML: 업무 시스템 문서인지 분류하고 의심 파일은 열지 않고 격리한다.

## 10. 집계 원칙

- 파일 수와 용량은 실제 파일 원장으로 집계한다.
- 프로젝트 수는 정규화된 프로젝트 키 기준이다.
- 수주액은 계약서 또는 고객 발주서에서 금액이 확인된 건만 포함한다.
- 견적액은 해당 프로젝트의 유효한 최신 매출 견적을 기본으로 사용한다.
- 매입 견적, 표준양식 잔존 시트, 참고 견적은 별도 집계한다.
- 같은 프로젝트의 견적 버전은 합산하지 않고 최신값과 변경 이력을 함께 제공한다.
- 프로젝트 범위와 금액 범위가 일치하지 않으면 금액을 억지로 배분하지 않는다.
- 누락값은 0이 아닌 `미확인`으로 표시한다.

## 11. API

- `GET /api/datasets`: 데이터셋 목록과 게시 상태
- `GET /api/datasets/{id}/runs`: 수집·처리 이력
- `GET /api/runs/{id}`: 처리 결과 요약
- `GET /api/runs/{id}/issues`: 검증 문제
- `GET /api/runs/{id}/preview`: 원본·정제값 비교
- `GET /api/datasets/{id}/records`: 게시 데이터
- `GET /api/dashboard/summary`: 경영 종합 현황
- `GET /api/projects` 및 `GET /api/projects/{id}`: 프로젝트 목록·상세
- `GET /api/files`: 파일 검색
- `GET /api/files/{id}/open`: 허용된 원본 파일 열기
- `POST /api/admin/reindex`: 변경분 재수집
- `POST /api/datasets/{id}/versions/{version}/publish`: 검토 완료 버전 게시

## 12. 보안과 원본 보호

- 원본 루트를 읽기 전용으로 사용한다.
- 파일 열기는 색인된 파일과 허용 루트 아래 경로만 허용한다.
- 실행 가능 파일과 격리 HTML은 다운로드·실행 링크를 제공하지 않는다.
- 경로 순회와 임의 SQL을 차단한다.
- 로컬 사내 사용을 기본으로 한다. 외부 공개 전 인증, TLS, 역할 권한과 감사 로그를 추가한다.

## 13. 오류 처리

- 한 파일의 추출 실패가 전체 수집 실행을 중단하지 않는다.
- 파일별 처리 상태와 오류 코드를 저장한다.
- 계산 불가 지표는 `미확인`으로 표시한다.
- 원본이 사라져도 과거 색인과 게시 버전은 유지하고 파일 열기만 비활성화한다.
- 부분 게시에는 제외된 데이터와 사유를 명시한다.

## 14. 검증

- 전체 파일 수와 용량을 원본 디렉터리와 대조한다.
- 연도·프로젝트·확장자별 합계가 전체 원장과 일치하는지 확인한다.
- MD5 중복 대표 파일과 그룹 수를 독립 계산으로 대조한다.
- 대표 프로젝트와 문서 유형별 샘플을 원문과 비교한다.
- 최신 견적 선택과 중복 제거 전후 금액을 검증한다.
- 원본·정제 비교와 검증 문제 상태 전이를 테스트한다.
- API 필터, 페이지네이션, 잘못된 ID와 경로 차단을 테스트한다.
- 데스크톱·태블릿에서 고려솔더 형식의 데이터셋 탐색과 표 스크롤을 검증한다.
- 작업 전후 원본 파일의 크기와 수정 시각이 바뀌지 않았음을 확인한다.

## 15. 단계별 구현

### 1단계: 파일 원장과 프로젝트 카탈로그

전수 스캔, 프로젝트 정규화, 중복·격리 분류, 파일 검색과 종합 파일 현황을 구현한다.

### 2단계: 업무 문서 분석

견적, 계약·발주, 거래 문서를 추출하고 원본·정제 비교와 검증 문제를 구현한다.

### 3단계: 설계·미디어 연결

도면·BOM과 사진·영상 메타데이터를 프로젝트 상세에 연결한다.

### 4단계: 검토·게시 운영 흐름

수집 이력, 검토, 부분 게시, 게시 버전과 재수집을 고려솔더 형식으로 완성한다.

## 16. 완료 기준

- 9,036개 원본 파일을 누락 없이 원장에 기록한다.
- 2025·2026 프로젝트와 반응기 12건을 통합 조회한다.
- 주요 업무 문서에서 추출한 값과 원본 근거를 함께 확인할 수 있다.
- 위험·임시·중복 파일이 운영 데이터와 분리된다.
- 고려솔더와 같은 데이터셋·수집·검증·게시 흐름이 작동한다.
- 경영 지표가 명시된 집계 규칙과 검증된 게시 데이터에 기반한다.
- 원본 파일이 변경되지 않는다.
- 자동 테스트, 프로덕션 빌드와 실제 브라우저 검증이 통과한다.
