# 경동글로벌텍 제조 포트폴리오 및 EDA·ML 확장 설계

## 1. 목적

`20261003 자료` 전체를 읽기 전용으로 색인해 경영진이 연도·고객·프로젝트·설비별 생산 및 영업 현황을 확인할 수 있는 제조 데이터 대시보드로 확장한다. 전체 자료는 제조 자산 현황과 프로젝트 근거에 사용하고, EDA와 ML 검토는 반응기·견적·수주·도면 관련 데이터에 집중한다.

성공 기준은 다음과 같다.

- 전체 제조자료를 원본 수정 없이 빠짐없이 색인한다.
- 경영 지표를 연도·고객·설비·프로젝트 단위로 탐색할 수 있다.
- 금액 지표와 분석 결과는 확인 가능한 견적·계약·발주 근거를 가진 데이터만 사용한다.
- EDA·ML 결과마다 사용 표본, 제외 표본, 기준일과 근거를 표시한다.
- 표본이 부족할 때 예측 정확도를 과장하지 않고 데이터 보강 방향을 제시한다.

## 2. 조사 기준 현황

- 전체 자료: 약 31GB
- `25 경동도면함`: 3,726개 파일, 약 12.2GB
- `26 경동도면함`: 4,983개 파일, 약 18.0GB
- 기존 `반응기_리포지토리`: 326개 파일, 약 0.31GB
- 주요 형식: JPG 4,831개, PDF 1,284개, DWG 754개, CAD 458개, XLSX/XLS 400개, 영상 101개
- 실행파일, 라이브러리, 임시·백업 파일과 업무 자료가 혼재한다.

파일 수는 원본 스캔 시점에 다시 계산하며, 운영 화면에는 최종 수집 실행의 기준 시각과 실제 집계를 표시한다.

## 3. 범위

### 포함

- 2025·2026 제조자료와 기존 반응기 정제 저장소
- 프로젝트, 고객, 설비·품목, 견적, 계약·발주, 도면, 문서, 사진·영상 메타데이터
- 연도·고객·설비·프로젝트별 경영 및 생산 현황
- 파일 변경 탐지, 중복 그룹, 분류 신뢰도와 데이터 품질 이슈
- 반응기 중심 EDA, 데이터 충분성 진단, 제한적 ML 실험
- 안전한 원본 파일 열기

### 제외

- 원본 파일 수정·이동·삭제
- 실행파일과 라이브러리 실행
- 사진·영상 내용의 AI 자동 판독
- CAD 형상의 임의 해석 또는 자동 설계 판정
- 표본 근거가 부족한 운영 예측이나 자동 의사결정
- 설비 자동 제어, 견적 자동 승인, 공개 인터넷 배포

## 4. 설계 원칙

### 전체 제조자료와 분석 데이터의 분리

전체 자료는 제조 자산 원장과 프로젝트 활동량 집계에 포함한다. 견적·수주 KPI, EDA와 ML은 근거 및 대상 범위가 확인된 반응기 관련 레코드만 사용한다. 이 구분은 화면과 API 응답에 명시한다.

### 근거 우선

금액, 고객, 품목, 일자와 프로젝트 연결에는 원본 파일 ID, 추출 방법, 원본값, 정제값과 신뢰 상태를 보존한다. 불확실한 값은 0이나 확정값으로 대체하지 않는다.

### 안전한 읽기 전용 처리

원본은 복사하거나 수정하지 않는다. SQLite에는 메타데이터와 추출 가능한 구조화 값만 저장한다. 위험 파일과 임시 파일은 통계에 별도 분류하고 열기 기능을 제공하지 않는다.

## 5. 데이터 아키텍처

### 핵심 엔터티

- `sources`: 2025, 2026, 반응기 정제 소스
- `ingestion_runs`: 수집 실행, 기준 시각, 처리 결과와 오류
- `files`: 상대 경로, 형식, 크기, 수정시각, 해시, 안전 분류
- `projects`: 프로젝트 키, 연도, 고객, 설비·품목, 상태와 기간
- `customers`: 정규화 고객명과 원문 이름
- `equipment`: 설비 유형, 용량, 재질과 주요 사양
- `project_files`: 프로젝트와 파일의 다대다 연결 및 신뢰도
- `quotes`: 견적번호, 발행자, 수신처, 품목, 금액, 버전과 유효성
- `orders`: 계약·고객 발주 근거, 금액, 수주일과 납기
- `drawings`: 도면번호, 종류, 개정 후보, 일자와 해독 상태
- `documents`: 계약, 발주, 거래, 검사, 성적서 등 문서 분류
- `quality_issues`: 분류·추출·중복·근거 누락 문제
- `analysis_runs`: EDA·ML 실행 조건, 표본, 결과와 평가 지표

### 프로젝트 정규화

- `KD25xx`, `KD26xx`, `GD25xx`, `GD26xx` 패턴을 프로젝트 후보로 추출한다.
- 폴더명, 파일명과 문서 내부 값은 원문 그대로 보존하고 별도 정규화 값을 만든다.
- 고객·프로젝트·설비가 불확실하면 `미분류`와 신뢰도 점수로 저장한다.
- 여러 프로젝트와 관련된 파일을 하나로 강제 배정하지 않고 다중 연결한다.
- 기존 `R01`부터 `R12`까지의 정제 프로젝트는 대응 KD/GD 코드에 우선 연결한다.

## 6. 수집 및 재색인

1. 전체 파일의 경로, 크기, 수정시각과 확장자를 수집한다.
2. 안전 정책에 따라 업무 파일, 미디어, 임시·백업, 실행 위험 파일로 분류한다.
3. 경로·파일명에서 연도, 프로젝트 코드, 고객과 설비 후보를 추출한다.
4. 지원 문서에서 텍스트와 표를 추출한다.
5. 견적, 수주, 도면과 문서 엔터티를 정규화한다.
6. 기존 반응기 정제 데이터와 연결하고 충돌을 품질 이슈로 기록한다.
7. 경영 집계와 분석용 뷰를 갱신한다.

재색인은 경로, 크기와 수정시각을 먼저 비교하고 변경 파일만 다시 처리한다. 해시는 신규·변경 파일에 계산해 중복을 판별한다. 파일 하나의 실패는 전체 실행을 중단하지 않는다.

## 7. 경영 및 생산 분석 화면

### 경영 현황

- 연도별 프로젝트 수, 고객 수, 견적액, 확인 수주액과 전환율
- 설비·품목별 프로젝트 및 금액 구성
- 신규·진행·완료·미확인 프로젝트 분포
- 최근 프로젝트 활동과 자료 증가 추이
- 지표별 사용 기준과 제외 건수

### 제조 프로젝트

- 연도, 고객, 프로젝트 코드, 설비·품목과 상태 필터
- 견적, 계약·발주, 도면, 문서, 사진·영상 수
- 프로젝트 상세에서 근거 파일과 데이터 품질을 함께 표시

### 견적·수주 분석

- 연도·고객·설비별 견적 및 수주 추세
- 매출 견적과 매입·참고 견적 분리
- 같은 견적의 변경 이력과 최신 유효본
- 프로젝트 건수 기준 견적→수주 전환
- 계약·발주로 확인되지 않은 금액의 명시적 제외

### 설비·도면 분석

- 설비 유형, 용량, 재질과 프로젝트 분포
- 프로젝트별 도면 수, 최신본 후보, 개정 활동과 해독 실패
- 도면이 없거나 최신본이 불확실한 프로젝트

### 전체 자료

- 연도, 고객, 프로젝트, 설비, 자료 유형과 확장자 필터
- 파일 수, 용량, 최근 수정, 중복과 격리 현황
- 허용된 업무 파일만 원본 열기

### 데이터 품질

- 미분류 프로젝트·고객·설비
- 금액·일자 추출 실패 또는 근거 누락
- 중복 파일과 버전 충돌
- 최신 도면 미확정, CAD 해독 실패, 경로 끊김
- 위험·임시·백업 파일 격리 현황

## 8. EDA 설계

EDA는 반응기·견적·수주·도면 관련 레코드만 대상으로 한다.

- 연도별 견적·수주액과 프로젝트 수
- 고객, 설비 유형, 용량과 재질별 분포
- 견적 금액, 수주 금액과 전환 여부의 관계
- 도면 수, 개정 횟수, 자료 완성도와 프로젝트 상태의 관계
- 납기 변경, 설계 변경과 문서 활동량
- 금액, 기간, 도면 수의 이상치와 근거 레코드
- 결측률, 중복률, 범주 불균형과 시계열 편향

각 결과에는 대상 조건, 사용 레코드 수, 제외 레코드 수, 기준일과 근거 링크를 표시한다.

## 9. ML 검토 설계

ML은 의사결정 지원을 위한 탐색 단계로 제한한다.

### 후보 과제

- 프로젝트 특성에 따른 견적금액 범위 추정
- 견적 프로젝트의 수주 전환 가능성 탐색
- 유사 반응기 프로젝트 검색
- 금액·도면 수·프로젝트 기간의 이상치 탐지

### 실행 조건

- 목표값과 입력 특성의 정의 및 근거가 명확해야 한다.
- 누출 가능성이 있는 수주 후 생성 정보는 학습 입력에서 제외한다.
- 범주별 최소 표본과 전체 유효 표본 수를 진단한다.
- 시간 순서를 고려한 검증 또는 교차검증을 사용한다.
- 기준 모델보다 의미 있게 개선되지 않으면 운영 모델로 게시하지 않는다.

### 표본 부족 시 출력

- 모델 점수 대신 데이터 충분성 진단
- 주요 영향 후보와 유사 프로젝트
- 추가 수집이 필요한 필드 및 최소 표본 제안
- 학습 제외 사유와 데이터 품질 문제

## 10. API 경계

- `GET /api/dashboard/summary`: 경영 종합 KPI와 추세
- `GET /api/projects`, `GET /api/projects/{id}`: 제조 프로젝트 목록과 상세
- `GET /api/portfolio/customers`: 고객별 현황
- `GET /api/portfolio/equipment`: 설비·품목별 현황
- `GET /api/portfolio/activity`: 프로젝트 및 자료 활동 추이
- `GET /api/quotes`, `GET /api/orders`: 견적·수주 분석
- `GET /api/drawings`: 도면 분석
- `GET /api/files`: 전체 자료 검색
- `GET /api/files/{id}/open`: 안전한 원본 열기
- `GET /api/quality/issues`: 데이터 품질 이슈
- `GET /api/analytics/eda`: EDA 결과와 표본 근거
- `GET /api/analytics/ml-readiness`: ML 데이터 충분성 진단
- `GET /api/analytics/similar-projects`: 유사 프로젝트
- `POST /api/admin/reindex`: 증분 재색인

## 11. 오류 처리와 보안

- 추출 실패는 파일별 오류 코드와 사유로 기록한다.
- 계산 불가능한 값은 `미확인`으로 반환한다.
- 원본이 사라진 파일은 메타데이터를 유지하고 열기만 비활성화한다.
- 색인된 허용 루트 내부 파일만 열 수 있으며 경로 순회를 차단한다.
- EXE, DLL, CAB, OCX, TLB, COM과 의심 HTML은 실행하거나 열지 않는다.
- 관리자 재색인은 초기 로컬 사용 범위에서만 제공한다.

## 12. 검증

- 원본 폴더와 전체 파일 수·용량 대조
- 연도·확장자·프로젝트별 합계와 전체 원장 일치 확인
- 대표 폴더별 프로젝트·고객·설비 분류 샘플 검증
- 증분 재색인 시 미변경 파일 재처리 방지
- 중복 그룹과 최신 견적 선택 규칙 검증
- 계약·발주 근거가 없는 금액의 KPI·학습 제외 검증
- EDA 표본 수와 제외 사유 재현성 검증
- ML 누출 방지, 기준 모델 비교와 교차검증 테스트
- API 필터, 페이지네이션, 잘못된 ID와 경로 차단 테스트
- 프런트엔드 프로덕션 빌드 및 실제 브라우저 검증
- 처리 전후 원본 크기와 수정시각 불변 확인

## 13. 단계별 구현

### 1단계: 전체 파일 원장과 프로젝트 카탈로그

증분 스캐너, 안전 분류, 프로젝트·고객·설비 후보, 파일 통계와 검색을 구현한다.

### 2단계: 경영·생산 데이터마트

프로젝트 정규화, 견적·수주·도면 연결과 연도·고객·설비별 집계를 구현한다.

### 3단계: 대시보드 확장

경영 현황, 제조 프로젝트, 견적·수주 분석, 설비·도면 분석, 전체 자료와 품질 화면을 구현한다.

### 4단계: EDA와 ML 준비도

재현 가능한 EDA, 데이터 충분성 진단, 유사 프로젝트와 조건부 기준 모델을 구현한다.

## 14. 완료 기준

- 전체 제조자료가 누락 없이 파일 원장에 기록된다.
- 연도·고객·프로젝트·설비별 현황을 필터링하고 근거까지 추적할 수 있다.
- 기존 반응기 12건과 전체 프로젝트 자료가 연결된다.
- 견적·수주 KPI가 확인된 근거와 명시된 집계 규칙에 기반한다.
- EDA 및 ML 준비도 결과가 표본과 제외 기준을 함께 제공한다.
- 위험 파일이 운영 자료 및 분석에서 분리된다.
- 증분 재색인, 자동 테스트, 프런트엔드 빌드와 브라우저 검증이 통과한다.
- 원본 파일이 변경되지 않는다.
