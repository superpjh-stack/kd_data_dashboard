# 경동글로벌텍 제조 데이터 대시보드

전체 제조자료의 연도·고객·프로젝트·설비 현황과 반응기 수주·견적·도면 분석을 연결한 React + FastAPI 대시보드입니다. 원본 경동 데이터는 읽기 전용으로 사용합니다.

## 2026-11-12 데이터 교체

`19년 도면함`~`26년 도면함` 폴더가 있으면 지정 도면함과
`경동글로벌텍_기초데이터_입력양식_v1.5.xlsx`만 색인합니다.
`History`와 예전 반응기 리포지토리는 이 모드에서 읽지 않습니다.
재시작과 재색인은 기존 반응기 프로젝트·견적·문서 테이블을 비운 상태로 유지하며,
입력양식 견적은 별도 검수 후보로 조회합니다. 확정 수주액이 없으면 미확인으로 표시합니다.

적재 범위는 원본 1,306개(DWG 1,305개 + XLSX 1개)입니다.
SHA-256 중복 제거 후 고유 DWG는 1,277개이며 정상 해석 1,255개,
부분 해석 6개, 실패 16개입니다. `analysis_drawings`와
`analysis_drawing_texts`에 추출 근거를 보존하며, 활성 파일의 SHA-256과
일치하는 분석만 조회합니다. 재색인은 파일 목록·해시·입력양식만 갱신하므로
새 DWG의 내부 분석은 별도 추출 작업이 필요합니다.

골든데이터셋 후보와 제안은 `outputs/golden-dataset-20261112/`에 있습니다.
자동 추출 후보는 학습 승인 데이터가 아니며 현재 승인 골든 표본은 0건입니다.
서비스의 **EDA · ML 검토 → 샘플 JSON 다운로드**에는 상세 제안도 포함됩니다.

## 실행

Python 3.11+, Node 22+, `uv`가 필요합니다.

```bash
export KYUNGDONG_DATA_ROOT="/절대경로/01 경동Data"
uv sync --extra dev
cd web && npm install && cd ..
./start-dev.command
```

현재 Mac에서는 `start-dev.command`에 전체 `01 경동Data` 경로가 기본값으로 설정되어 있어 환경변수 없이 실행할 수 있습니다. 상위 폴더를 지정하면 내부의 `20261003 자료/반응기_리포지토리`를 자동으로 찾아 연결합니다.

브라우저에서 `http://127.0.0.1:5178`을 엽니다. API는 `http://127.0.0.1:8021`입니다.

프로덕션 정적 빌드:

```bash
cd web && npm run build && cd ..
export KYUNGDONG_DATA_ROOT="/절대경로/01 경동Data"
uv run uvicorn dashboard.run:app --host 127.0.0.1 --port 8021
```

## 기초데이터 입력양식 적재

```bash
uv run python -m dashboard import-foundation --workbook "/절대경로/경동글로벌텍_기초데이터_입력양식_v1.5.xlsx"
```

`KYUNGDONG_DB_PATH`에 지정한 DB(기본 `.runtime/kyungdong.sqlite3`)로 적재합니다.
기존 DB는 적재 전에 SQLite backup API로 백업하는 것을 권장합니다.
원본 엑셀은 수정하지 않으며 DB 옆 `foundation-sources` 폴더에 SHA-256별 원본을 보관합니다.
DB를 이동하거나 배포할 때 이 폴더도 함께 옮겨야 원본 다운로드가 동작합니다.

- 동일 파일은 다시 적재해도 중복되지 않습니다. 다른 내용의 파일은 이력을 보존하고 최신 적재본만 화면에 표시합니다.
- 일반 입력 시트의 6행 예시·수식만 있는 빈 행을 제외합니다. 회사정보·안내·코드 시트는 각 시트 구조에 맞게 처리합니다.
- 원본 시트·행·셀·수식·저장된 계산값을 보존합니다. 수식은 재계산하지 않습니다.
- 하늘색 셀이 포함된 행은 설계안으로 표시합니다. 필수값·조건부 필수값·코드 참조·날짜·복합 업무 키를 검사합니다.
- 견적 단가는 유형·대상·단위·유효시작일, 도면은 도면번호·Rev, 견적은 번호·일자로 중복을 검사합니다.
- 신규 견적과 기존 견적의 정규화한 번호가 같으면 중복 후보로 표시합니다. 실제 같은 거래라는 판정은 아니며 자동 병합하지 않습니다.
- 신규 자료는 기존 반응기 견적·수주 KPI에 합산하지 않습니다. 사용자 입력 행은 검토용 데이터이며 로그인 계정을 생성하지 않습니다.
- 재색인과 서버 재시작은 기초데이터 적재본을 삭제하지 않습니다.

메뉴는 고려솔더와 같은 `워크스페이스 / 데이터셋 / 품질·분석 / 지식 검색`으로 구성합니다.
`DB 적재현황`에서 시트별 건수와 검수 상태를 확인하고, `원본 대조`에서 셀까지 추적할 수 있습니다.
RAG 메뉴는 문서 목록과 공개 범위를 조회하며 문서 본문 검색·임베딩·AI 답변 기능은 포함하지 않습니다.

2026-10-28 v1.5 적재 결과: 입력 555행, 참고자료 91행, 검수 필요 168행,
설계안 포함 356행, 기존 견적번호 중복 후보 25행입니다. 신규 견적 133건 중 금액은 132건,
실제 원가는 0건 입력되어 있어 원가 예측용 표본을 추가 확보해야 합니다.

## 데이터 기준

- 프로젝트·설계·BOM: `bom/data/cases_pipeline.json`
- 문서: `index/files.csv`
- 견적: `index/quotes.csv`
- 전체 제조자료: `25 경동도면함`, `26 경동도면함`과 `반응기_리포지토리`
- EDA·ML: 반응기·견적·수주·도면 관련 유효 표본만 사용
- 수주액: 계약·고객 발주 금액이 확인된 건만 포함
- 유효 견적액: `해당건견적=O`, `경동 발행`, R12 전체 플랜트 견적 제외

공개 네트워크에 배포하기 전에는 인증, TLS, 감사 로그를 추가해야 합니다.
